# Notes for Claude

Goal: a monthly, ranked list of the actions that cut spending most, plus a clear view of goals and net worth. Eleven visible tabs (the user added Home scenarios, Notes and Transfers To Do; Transactions is hidden); don't add more without asking. Home scenarios' Selected scenario resizes the House deposit goal that takes monthly savings on each refresh (the one place the script writes a Targets amount). Read the live sheet with `python3 scripts/read-sheet.py` (uses the clasp login). Personal finance pipeline: Apps Script (apps-script/finance-sync.gs) syncs Akahu (NZ banks) and Wise into a Google Sheet; the skill in .claude/skills/personal-finance-review/ produces ranked savings actions and runs the monthly review. .claude/skills/finance-setup/ is the first-time setup once the feeds sync: accounts, income sources, rules, base and stretch goals, budget, email.

- Never ask for, print, or commit tokens. They live in Apps Script Script properties.
- Keep the script read-only. Don't add payment, transfer, or conversion calls, even though the APIs support them.
- Tabs are read by column index. Transactions: Transaction ID col 9, Amount (NZD) col 11, Reference col 12. Accounts: Balance (NZD) col 6, Provider col 9. Only add columns at the end, add them to HEADERS (setup() extends old header rows), and check every reader: sync(), recategorise(), markOwnTransfers_(), nzdAmount_(), buildSummary_(), buildMerchants_(), buildNetWorth_(), dashboardData_(), forecastData_(). Targets (Share of savings col 10, Paid from col 11) and Actions are read by index too.
- Number logic lives in plain functions (parseRules_, myCategory_, pairTransfers_, netWorthData_, dashboardData_, forecastData_) so it can be tested in Node without a spreadsheet. Keep sheet reads and writes out of them. Run `node tests/finance-sync.test.js` after any change to the script, and add a case for new logic.
- Keep personal information out of git: no names of people or payers, balances, amounts from the user's data, emails or IDs in tracked files. The engine is tracked; everything about the user is in the sheet or a gitignored `my-*` file (my-rules.gs, my-actions.gs, the skill's my-preferences.md), each with a committed `.example`. When adding a new kind of personal setting, give it a `my-*` file and a `.example`, and add it to scripts/setup-local.sh. `scripts/check-private.py` runs as the pre-commit hook and on GitHub; never bypass it (no --no-verify, no git add -f); `scripts/agent-guard.py` enforces that in Claude Code and refuses any git command that mentions those flags, so make doc edits that name them with the editor, not the shell. Commit messages describe code changes only: no amounts or anything from the user's data. Tests use made-up names and numbers and must pass from the `.example` files alone.
- When the user asks to categorise a payee, add a rule to `apps-script/my-rules.gs` (specific rules above the `*` catch-alls), run the tests, `clasp push`, and ask them to use Finance > Recategorise and refresh. To change an existing Categories row, add it to `MY_RULE_EDITS` in the same file (applied on the next Recategorise or Sync).
- The user likes managing Targets (goals, limits, planned purchases) and Holdings from chat. Edit them directly with the Google Sheets connector (its Google account has edit access; the spreadsheet ID is parentId in apps-script/.clasp.json). Only write yellow cells (EDITABLE_COLS in the script); everything else is generated and gets overwritten. Read the range first so you don't clobber edits made in the sheet, write dates as yyyy-mm-dd (and set Holdings' Last updated yourself when you change a balance: the sheet's auto-stamp only fires on hand edits), then ask them to use Finance > Recategorise and refresh to refresh the Forecast.
- Subscriptions the user tells you about go in `MY_SUBSCRIPTIONS` in `apps-script/my-rules.gs`, so the Dashboard shows them as soon as they charge.
- Savings actions Claude works out go in `apps-script/my-actions.gs` (MY_ACTIONS); the next Recategorise or Sync adds any not yet on the Savings actions tab. Never overwrite rows already on the tab.
- Deploy with `cd apps-script && clasp push`. Test by running `sync` in the Apps Script editor and checking the execution log.
- Keep docs plain: short, direct, minimal formatting.
- Transfers To Do tab: one-off moves Claude recommends (outside the payday split) go in its One-off transfers section with the connector: Transfer ("From → To"), Amount, Status (To do), Why, in rows under the section's header row and above "Your routine" (read the tab first; insert a row if there's no blank one). The script keeps them across refreshes; never remove rows the user marked Done unless asked.
- Notes tab: questions and concerns to take to an accountant, adviser, bank or the user themself (Topic, Question or concern, Ask, Status Open/Done, Notes, Added). When something comes up that needs a professional or a decision, add a row with the connector; mark rows Done when resolved. Don't give personalised investment or tax advice; put the question here instead.
- The sheet refreshes itself each morning around 7am once the user has run installAutoRefresh (a full sync), so changes made with the connector or clasp push show up then, or straight away if the user runs Recategorise and refresh. Claude can't run Apps Script functions or click the sheet's menus.
- The money email (sent Fridays only from dailyRefresh; dailyEmailData_ for the numbers and words, dailyEmailHtml_ for the layout) is plain text with bold, a cheeky coach voice, and a subject with no money words so mail sorters don't file it as a receipt. Preview changes with `node scripts/preview-email.js` and show the user before deploying.
